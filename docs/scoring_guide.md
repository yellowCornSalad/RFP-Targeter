# 점수 산정 기준 (Scoring Guide)

> **단일 진실 원천**: 본 문서는 [src/rfp_targeter/scoring/](../src/rfp_targeter/scoring/) 의 코드와 1:1 대응.
> 코드 수정 시 본 문서도 함께 업데이트해야 함.

## 종합 점수 공식

```
total = kw × 0.35 + bg × 0.10 + cs × 0.20 + cp × 0.20 + tr × 0.15
      + theme_fit 보너스
```

### theme_fit 보너스 (별도 가산)

| theme_fit | 보너스 |
|-----------|--------|
| ≥ 80 | total **+10** |
| ≥ 60 | total **+5** |
| < 30 | total **−5** |
| 그 외 | 0 |

가중치는 [config/settings.yaml](../config/settings.yaml) 의 `scoring_weights` 에서 조정 가능.

---

## 5축 산정 기준 (각 0~100점)

### 1. 키워드 적합도 — `kw` (가중치 35%)

회사 핵심 키워드가 공고에 얼마나 등장하는가.

| 항목 | 점수 |
|------|------|
| 회사 `core_keywords` 매칭 | 매칭당 **+12** |
| `positioning_keywords` 매칭 | 매칭당 **+8** |
| 보안 필터 추가 매칭 (`matched_keywords` − core) | 매칭당 **+4** |
| 최대 | 100 |

> **예**: core 2개 + positioning 1개 + 보안필터 추가 5개 매칭
> → 2×12 + 1×8 + 5×4 = **52점**

source: [scoring/keyword.py](../src/rfp_targeter/scoring/keyword.py)

---

### 2. 예산 적합도 — `bg` (가중치 10%)

공고 예산이 회사 적정 범위(`profile.yaml > budget_range`) 와 얼마나 일치하는가.

| 조건 | 점수 |
|------|------|
| Sweet spot 내 (800~3000 백만원) | **100** |
| 회사 범위(200~5000) 내, sweet spot 밖 | **60~100** (선형) |
| 너무 작음 (회사 min 미만) | **20** |
| 너무 큼 (회사 max 초과) | **25** |
| 정보 없음 | **35** (정보 부족 페널티) |

> 본 공고문 텍스트에 예산이 안 적힌 경우(KISA 입찰공고 다수)는 35점.
> 첨부 PDF 본문에 있는 경우는 추후 PDF OCR 확장 시 잡힘.

source: [scoring/budget.py](../src/rfp_targeter/scoring/budget.py)

---

### 3. 컨소시엄 부담 — `cs` (가중치 20%)

회사가 단독 수행 가능한가, 외부 파트너 필요한가. **부담이 적을수록 점수 높음**.

| 신호 | 효과 |
|------|------|
| 시작 점수 | **100** |
| "대학·산학" 신호 + 회사 KAIST 활용 가능 | **−5** |
| "대학·산학" 신호 + 회사 파트너 미설정 | **−35** |
| "컨소시엄·공동연구" 신호 + 회사 max_partners≥3 | **−10** |
| "컨소시엄·공동연구" 신호 + 회사 max_partners<3 | **−30** |
| 컨소시엄 신호 없음 + 회사 단독수행 가능 명시 | 100 유지 |
| 컨소시엄 신호 없음 + 단독수행 미명시 | **−10** |

> KAIST 공동특허 등록되어 있어 `university_partner_available: true` → 대학 필요 공고에서도 점수 거의 안 깎임.

source: [scoring/consortium.py](../src/rfp_targeter/scoring/consortium.py)

---

### 4. 경쟁 강도 — `cp` (가중치 20%)

경쟁이 적을수록 점수 높음.

| 신호 | 효과 |
|------|------|
| 시작 점수 (baseline) | **50** |
| 전문 영역 키워드 매칭 (양자내성·PQC·AI 보안·공격 시뮬레이션·보안성 검증) | 매칭당 **+15** (최대 +40) |
| 대형 경쟁 영역 매칭 (통합 플랫폼·관제·SOC·SIEM) | 매칭당 **−15** (최대 −35) |
| 본문에 회사 경쟁사 이름 명시 (안랩·SK쉴더스 등) | **−15** |
| 본문 200자 미만 (정보 부족) | **−5** |

> "AI 보안 레드팀 로드맵" 같은 공고는 "AI 보안" 매칭으로 50+15=65점.
> "SIEM 통합 관제 플랫폼 구축" 같은 공고는 50−30=20점 (대기업 강한 영역).

source: [scoring/competitor.py](../src/rfp_targeter/scoring/competitor.py)

---

### 5. 기술 성숙도 적합 — `tr` (가중치 15%)

공고에서 요구하는 TRL과 회사 보유 기술 TRL의 차이.

| 조건 | 점수 |
|------|------|
| 회사 TRL과 정확히 일치 | **100** |
| Gap 1 | **85** |
| Gap 2 | **65** |
| Gap 3 이상 | **40** |
| 공고 본문에서 TRL 추정 불가 | **45** (정보 부족 페널티) |
| TRL 추정 가능하나 회사 보유 TRL 데이터 없음 | **50** |

> 공고에서 TRL 추정 단서: "TRL 7~8", "실증·사업화" → 7, "기초연구·탐색" → 3, "원천기술·응용연구" → 5.

source: [scoring/trl.py](../src/rfp_targeter/scoring/trl.py)

## 별도 지표: 테마 적합도 — `theme_fit`

회사 본업과의 매칭 강도. **5축 가중합에는 포함되지 않지만**, 위의 보너스 규칙으로 종합 점수에 영향.

| 항목 | 점수 |
|------|------|
| 시작 점수 (baseline) | **25** |
| 회사 보유 기술(`technologies`) 매칭 | 매칭당 **+15** (최대 +40) |
| `core_keywords` 매칭 | 매칭당 **+4** (최대 +20) |
| `positioning_keywords` 매칭 | 매칭당 **+6** (최대 +15) |
| `matched_keywords` 6개 이상 | **+25** |
| `matched_keywords` 3~5개 | **+15** |
| `matched_keywords` 1~2개 | **+8** |
| 본문 1500자 이상 (정보 풍부) | **+3** |
| 최대 | 100 |

> 회사 핵심 OFFen 키워드(AI DAST·LLM 기반 자율 공격 등)는 정확 매칭되기 어려우니, `matched_keywords` 풍부도가 큰 기여.

source: [scoring/keyword.py:score_theme_fit](../src/rfp_targeter/scoring/keyword.py)

## 실제 사례 — KISA 입찰공고 Top 3

| 순위 | 제목 | total | kw | bg | cs | cp | tr | theme |
|------|------|-------|-----|-----|-----|-----|-----|------|
| 1 | 단가계약 업체 등록(특허분야) | **61.0** | 28 | 35 | 100 | 80 | 45 | **68** (+5 보너스) |
| 2 | AI보안·정보보호 법제연구반 | **59.6** | 24 | 35 | 100 | 50 | 85 | **68** (+5 보너스) |
| 3 | AI 보안 레드팀 로드맵 | **58.9** | 36 | 35 | 100 | 80 | 45 | 50 |

**왜 1위가 단가계약(특허분야)인가?**
- 키워드: "특허" 키워드 매칭 + 회사 특허 38건 = theme_fit ↑
- 컨소시엄: 단독 수행 가능 신호 (100)
- 경쟁: 전문분야 가산 (+30)
- theme_fit 68 → 종합 +5 보너스

**왜 AI 보안 레드팀이 3위인가?**
- 키워드 점수는 가장 높음 (36점, 매칭 키워드 9개)
- 하지만 theme_fit 50 (60 미만이라 보너스 없음) → +5 못 받음
- 본문에 회사 보유 기술명(OFFen, AI DAST 등) 직접 매칭 약함

## 가중치 조정하려면

`config/settings.yaml`:

```yaml
scoring_weights:
  keyword: 0.35      # 핵심 키워드 매칭 — 가장 결정적
  budget: 0.10       # 예산 적정 — 정보 부족 케이스 많아 비중↓
  consortium: 0.20   # 컨소시엄 부담
  competitor: 0.20   # 경쟁 강도
  trl: 0.15          # 기술 성숙도 적합
```

합이 1.0 이어야 함. 다음 `scripts/run_once.py` 또는 자동 폴링 사이클부터 적용.
