## 1. 한 줄 정의

> **AI 시대 오펜시브 보안의 실증 기반 통합 platform 기업** —
> 글로벌 컨센서스 "The moat is the system, not the model" 을 5년간 누적 자산(23.8만 건 DB, 22건 등록 특허, 화이트해커 인적 자원)으로 구현.

## 2. 시장 포지셔닝

### 2.1 시대 인식
- **"AI를 전제로 한 보안 패러다임 재설계"** 가 시장 방향
- AI 오펜시브 성능은 이론이 아닌 현실 — SAST 분야에서 Mythos·범용 LLM이 수천 개 zero-day 자율 발견 입증
- 당사 자체 RedTeam CTF에서도 해커 지망생 다수가 AI 활용 진단 수행 + 다단계 침투까지 AI 활용 일반화
- **결론**: AI를 위협으로만 보는 접근은 무의미. AI 활용 공격이 일반화되었음을 전제로 시장에 접근

### 2.2 경쟁력 재정의

| 더 이상 경쟁력이 아닌 것 | AI 시대의 진짜 경쟁력 |
|--------------------------|----------------------|
| 어떤 프레임워크를 도입했는가 | 실제 대응 시간을 얼마나 줄였는가 |
| 어떤 규정을 준수하고 있는가 | 운영 비용을 얼마나 절감했는가 |
| 어떤 평가 기준에 따랐는가 | 잠재된 위협을 얼마나 식별했는가 |
| 어떤 형식적 객관성을 갖추었는가 | 식별된 위협을 얼마나 제거했는가 |

→ **프레임워크·규정·인증은 출발점일 뿐. 실제 운영 환경에서 측정 가능한 성과(대응 시간·비용·식별 수·제거 수)가 시장 경쟁력의 결정 기준.**

### 2.3 핵심 메시지 (제안서 헤드라인용)
- "AI가 많이 찾는 시대 — 발견 수가 아니라 **우선순위**가 모든 것을 결정한다"
- "시뮬레이션이 아닌 **실증 기반** 보안 평가" (BAS 유사 효과 + 실제 침투 검증)
- "단일 platform 통합 — 외부 식별 → 침투 검증 → 내부 확산 자동 연계"
- "외산 AI에 민감정보 전송 불가 시장 확대 = 당사 포지셔닝 정합" (EU AI Act, 일본 ISMAP, 사우디 PDPL 등)

## 3. 4단계 자동화 모델

AI 공격이 외부 진입부터 내부 확산까지 전 단계를 공략하듯, 방어도 전 단계 자동화 필요. 당사는 4단계 영역을 **단일 platform**에서 통합 제공.

| 단계 | 영역 | 당사 제공 |
|------|------|----------|
| ① | 외부 자산 식별 | **OFFen ASM** — 외부 노출 자산 자동 식별 + 신뢰도 평가 |
| ② | 공개(N-Day) 취약점 식별 | **OFFen ASM** — CVE 매핑, 설정 결함 점검, 공격표면 분석 |
| ③ | 신규(0-Day) 취약점 식별 + 침투 가능성 검증 | **OFFen PTaaS + AI DAST** — 실제 침투 시도로 악용 가능성 실증 |
| ④ | 내부 침투 자동화 (내부 취약 지점 식별) | **OFFen RED** — 기업 내부망에서 ①~③ 동일 수행, 모든 자산 빈틈 없는 점검 + 공격 경로 자동 분석 |

### 4단계의 차별적 의미
- 기존 보안 도구는 단계별 분리 → 사람이 수동 연결
- OFFen은 **단일 platform 통합** — 외부 식별 결과가 즉시 침투 검증으로, 침투 결과가 즉시 내부 확산 검증으로 자동 연계
- **공격자 관점의 전체 시퀀스를 그대로 자동화** — 실제 침해 시나리오에 부합

## 4. OFFen 제품 라인업 (3대 제품)

### 4.1 OFFen ASM (Attack Surface Management)
> 외부 공격표면 관리

**주요 기능**
- 공개 취약점·신규 취약점 대응
- 설정 미흡·구성 결함 점검
- 외부 노출 자산 상시 식별 + 신뢰도 평가
- Shadow IT 식별 및 관리

**타깃 시장**: 대기업·공공·금융·중소 **전 영역**

---

### 4.2 OFFen AI Hacker (AI DAST)
> AI 자율 침투 진단 — SaaS / On-Premise

**주요 기능**
- **LLM 기반 자율 공격형 웹 취약점 검증** (KISA 2026 신기술 사업화 — AI 보안 유망기업 선정)
- 다단계 침투 자동 수행 + 자율 피드백 학습
- SaaS — 클라우드 구독 / On-Premise — 폐쇄망·규제 산업
- On-Premise는 **외산 AI 전송 불가 시장(금융·국방·중동·일본)** 대응 가능

**타깃 시장**: 정부·금융·통신·국방 + 규제 산업

---

### 4.3 OFFen RED
> 내부 침투테스트 자동화 솔루션

**주요 기능**
- 내부 ASM — 내부 자산 식별 + 실시간 모니터링
- 전 포트 스캔 + 서비스 핑거프린팅 + 위험도 분류
- **Smart Crawling · Smart Pathing** — 공격 경로 자동 분석
- AI 기반 실시간 공격 계획 수립 + 통제 가능한 자동 침투테스트 수행
- AI DAST 결합 — 공격자 관점 자동 보안 검증
- 자동 보고서 생성 + 조치 워크플로우 + 이행 추적 관리

**타깃 시장**: 금융·국방·핵심 인프라·대기업 그룹사

---

### 4.4 라인업의 통합 가치
- **ASM이 식별 → AI Hacker가 검증 → OFFen RED가 내부 확산 시뮬레이션**
- 각 단계 결과가 자동 연계 — 사람의 수동 통합 불필요
- 공격 시퀀스 전체 자동화 — 단일 platform에서 외부 진입부터 내부 확산까지
- **BAS 유사 효과 + 실제 침투 검증 = 시뮬레이션이 아닌 실증 기반 보안 평가**

## 5. 본질적 차별점 — 시스템·데이터·하네스

> **Mythos 쇼크(2026.04.07) 이후 글로벌 보안 업계가 도달한 결론** —
> 엔키화이트햇이 5년간 구축해 온 차별화의 본질과 일치.

### 5.1 AI 보안 진짜 경쟁력 = "어떤 모델을 쓰느냐" 가 아니라 "어떻게 운영하느냐"

| 영역 | 모델 의존도 | 시스템·DB·하네스 의존도 |
|------|------------|------------------------|
| 단순 코드 패턴 발견 | 높음 | 낮음 |
| 실제 운영 환경 침투 | 중간 | 높음 |
| 다단계 침투 자동화 | 중간 | **매우 높음** |
| 조직 보안 성숙도 평가 | 낮음 | **결정적** |
| 우선순위 판단 | 낮음 | **결정적** |

### 5.2 글로벌 보안 업계 컨센서스 — "The moat is the system, not the model"

| 출처 | 핵심 인용 |
|------|----------|
| **AISLE** | "작은 오픈 모델(3.6B)도 Mythos flagship 익스플로잇 8개 중 8개 감지. 27년 묵은 OpenBSD 버그도 5.1B 오픈 모델이 복구. AI 사이버보안의 moat는 모델이 아니라 시스템." |
| **Strobes** | "model(raw intelligence) ≠ harness(보안 워크플로) ≠ platform(공격표면·CTEM). 더 똑똑한 AI가 침투테스트 platform을 대체하지 않는다." |
| **Aikido** (1,000 AI 침투테스트 분석) | "효과성은 모델 능력보다 컨텍스트에 좌우. 화이트박스가 그레이박스 대비 critical 7배 발견. AI는 application security context를 더 가치있게 만든다." |
| **ArmorCode** | "AI 스케일 발견은 AI 스케일 노이즈가 될 위험. 핵심은 발견이 아니라 우선순위와 실행." |

### 5.3 엔키화이트햇이 5년간 구축한 시스템·DB·하네스 자산 (재현 불가 자산)

- **23.8만 건 해커 지식 DB** — 10년 축적, **자체 생성 55%** (NDA 기반 실전 침투 결과)
- **자율 공격 시나리오 엔진 + 피드백 루프** — 공격 실패 시 페이로드 적응 진화
- **한국 환경 특화 시나리오** — 국내 기업 구성·관행·블랙박스 환경 최적화
- **화이트해커 인적 자원 결합형 운영 구조** — 데이터 생산자가 모델 고도화 주체
- **북·중·러 국가배후 위협 그룹 TTP 직접 추적** — 범용 CTI 의존 경쟁사와 격차
- **Localized AI 침투테스트 프레임워크** — 시장·산업별 파인튜닝 가능
- **특허 38건 (등록 16건 + 출원 22건, 국외 3건 포함) + 핵심 기술자료 2년 임치** — IP 자산화 (전체 리스트는 §10 참조)

> **Mythos가 강력해질수록 "누구나 강력한 모델에 접근 가능"한 시대가 온다. 그 시대의 차별화는 모델이 아닌 시스템·DB·하네스에 있고, 이는 자본만으로 단기에 복제할 수 없는 5년 이상의 누적 자산이다.**

## 6. AI 진단의 부작용 — 우선순위 마비

### 6.1 AI 도입의 의도치 않은 부작용

| 부작용 | 조직 영향 |
|--------|----------|
| 버그바운티 패치 GAP | AI가 발견한 버그를 패치하기 전 공격자가 활용하는 시간차 발생 |
| 개발 생산성 저하 | 대량 발견 취약점 처리에 개발진 리소스 과다 소모 — 본업 정체 |
| 허위 리포트 검토 공수 증가 | 정오탐 판별·검증에 운영팀 부담 폭증 — AI 도입 ROI 상쇄 |
| 우선순위 마비 | 수천 개 발견 항목 중 무엇부터 처리할지 판단 불가 — 결정 마비 |

### 6.2 결정적 인식 전환
- AI가 "많이 찾는 것"은 더 이상 차별화가 아님 — 누구나 AI를 쓰면 발견량은 폭증
- 오탐이 많은 진단은 오히려 조직에 해가 됨 — 진단 결과를 신뢰할 수 없게 됨
- **진짜 가치는 "어떤 것이 진짜 위험한가"를 정확히 판단하는 능력** — 우선순위 결정
- AI 시대 보안 도구의 평가 기준 = "발견 수"가 아닌 **"실행 가능한 결과의 정확성"**

### 6.3 엔키화이트햇의 우선순위 판단 메커니즘
- **자산 신뢰도 평가** — 실제 운영 자산 우선
- **공격 가능성 기반 위험 판단** — 이론적 CVE가 아닌 실제 PoC 실행 가능 여부로 우선순위 결정
- **공격 시나리오 맥락** — 단일 취약점이 아닌 전체 공격 경로상의 중요도 평가
- **보안 운영 컨텍스트 반영** — 자산 비즈니스 중요도·노출도·EOL·보안 설정 종합 가중
- **오탐 자동 제거** — 스크린샷·본문 유사도·정규화 데이터 분석 기반 자동 검증

## 7. 보안 성숙도 정량 평가 — "우리 보안 어떻습니까?"에 답하는 능력

> 형식적 인증 보유는 답이 아니다. OFFen은 보안 태세를 **정량적으로 표현 가능한** 제품을 제공.

### 7.1 자산 3단계 자동 분류

| 등급 | 기준 | 조치 우선순위 |
|------|------|-------------|
| 위험 | 공격 성공(실제 침투 가능 입증) + 다수 취약점 + 핵심 자산 | 즉시 차단·패치 |
| 주의 | 공격 부분 성공 / 노출 자산 / 설정 결함 / 신규 CVE | 단기 대응 |
| 양호 | 공격 차단됨 + 설정 적정 + 패치 최신 | 주기적 재검증 |

### 7.2 보안 태세 종합 표현 — 정량 평가 데이터
- 자산별 공격 성공·실패(차단) 여부 — 실증된 침투 가능성
- 침투 시나리오 경로 시각화 — 외부 진입점~내부 확산 경로 매핑
- 취약 포트·서비스 수 — 외부 노출 위험 정량화
- 취약점 수 (위험/주의/양호별) — CVE·설정 결함·구성 오류 합산
- 공격 가능 자산 비율 — 전체 자산 대비 침투 가능 자산 비중
- 핵심 자산 침투 차단율 — 비즈니스 중요 자산의 방어 성공률

### 7.3 기존 평가 방식과의 차별

| 기존 | OFFen |
|------|-------|
| "ISMS-P 인증 보유" → 형식적 객관성 | "외부 자산 1,247개 중 위험 23개, 주의 156개, 양호 1,068개 / 침투 성공 자산 5개 / 평균 대응 시간 4.2시간" → **실증 정량성** |

→ **임원진·이사회 보고에 즉시 사용 가능한 객관 지표 제공**

## 8. BAS 대비 차별점 — 실제 침투 검증

| 구분 | BAS (SafeBreach·AttackIQ·Cymulate 등) | OFFen (엔키화이트햇) |
|------|---------------------------------------|---------------------|
| 검증 방식 | 공격 시뮬레이션 — 가상 페이로드 | 실제 침투 시도 — 진짜 공격 실행 |
| 결과 의미 | 방어 도구가 탐지했을 가능성 | 방어가 실제로 차단했는가 |
| 오탐 가능성 | 있음 — 시뮬레이션의 한계 | 낮음 — 실제 결과 기반 |
| 방어 검증 | 도구 설정 검증 중심 | 엔드투엔드 방어 능력 검증 |
| 증적 가치 | 내부 점검용 | 임원·이사회·**규제기관 보고 가능** |

### OFFen의 실증 기반 차별점
- 취약점이 "존재"하는지가 아닌 **"악용 가능한지"** 확인 — PoC 실제 실행
- 공격 경로가 "가능"한지가 아닌 **"실제로 도달하는지"** 검증 — Lateral Movement 실증
- 방어 도구가 "설정"되었는지가 아닌 **"실제로 차단하는지"** 측정 — End-to-End 검증
- 결과는 시뮬레이션 리포트가 아닌 **침투 증적** — 조치의 우선순위와 효과를 객관적으로 입증

> **BAS는 "우리 방어 도구가 가상의 공격을 막을 가능성"을 보여준다. OFFen은 "우리 환경이 실제 공격에 얼마나 안전한가"를 입증한다. AI 공격이 일반화된 시대에는 후자만이 의미 있는 평가다.**

## 9. 정부 공식 검증 — KISA 2026 신기술 지원사업 선정

> 엔키화이트햇의 방향성은 시장 가설이 아니라 **정부 공식 검증을 받은 정책 정합 사업**.

### 9.1 KISA 2026년 정보보호 신기술 지원사업
- **총 120억 4천만 원 규모** — 18개 과제, 50개 수행기업 선정 (**2026.05.08 발표**)
- 4대 분야:
  1. AI 기반 차세대 보안 제품 상용화
  2. AI 보안기업 육성
  3. 한국형 통합보안 모델
  4. 제로트러스트
- **엔키화이트햇 선정** — AI 보안기업 육성 사업화 분야
- **선정 과제명**: 「LLM 기반 자율 공격형 웹 취약점 검증 플랫폼」

### 9.2 선정의 의미
- Mythos 발표(2026.04.07) **한 달 만에** 정부가 동일 영역에서 당사를 공식 선택
- OFFen AI Hacker(AI DAST) 단독 제품화 방향성에 정부 공식 검증
- "외산 AI 직접 활용 vs 국내 자체 AI 침투 검증" 시장 구도에서 **정부가 후자에 베팅**
- **공공·금융·국방 진출 시 정부 사업 레퍼런스로 활용 가능**

### 9.3 글로벌 정책·규제 흐름도 동일 방향
- **EU AI Act** (2025.08 전면 시행) — 공격형 AI 도구 일부 금지, 현지 검증 요구
- **미국 Cyber Safety Review Board** — AI 사고 의무 공시 권고안 2026 Q3 예정
- **한국 KISA AI 보안 안내서 발간** — 외부 AI 위협에서 모델·서비스 보호
- **일본 ISMAP·사우디 PDPL** — 데이터 주권 + 현지 검증 요구

→ **외산 AI에 민감정보 전송 불가 시장 확대 = 당사 포지셔닝 정합**

## 11. 표준화 활동 — 국내 21건 + 국외 7건 (자료 §1-2-6)

### 11.1 국내 표준 (주요 21건)

- `TTAK.KO-12.0221` (2014.12) — 자산 가치 및 위험 수준 기반 리스크 점수 산출
- `TTAK.KO-12.0262` (2014.12) — 공격 차단율, 오탐률 등 성능 지표 측정

**위협 정보 표현 표준 (STIX 시리즈, 10건)** — 위협 인텔리전스 표준 주도
- `TTAE.OT-12.0019-Part1~5` (2018.12) — STIX 2.0 5개 파트 전체
- `TTAK.KO-12.0338` (2018.12) — STIX 2.0 유스케이스
- `TTAK.KO-12.0326` (2018.06) — STIX 기반 위협 정보 공유와 레거시 탐지 체계 연동
- `TTALOT-12.0020-part1~3` (2016.12) — STIX 1차 표준

- RFP 6번 "표준화 전략" 섹션에서 "표준화 참여 실적"으로 그대로 활용 가능
